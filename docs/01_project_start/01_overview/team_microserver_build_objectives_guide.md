# Team-Microserver 구축 목표

## 1. 문서 개요

본 문서는 **Team-Microserver 프로젝트가 최종적으로 구축하고자 하는 목표와 방향을 정의**한다.

다수의 금융서비스 구축 프로젝트에 적용해 온 **Microserver 프레임워크의 검증된 구조와 기능을 기반으로**, 프로젝트 생성부터 공통 기능과 애플리케이션 기능을 단계적으로 직접 구현하여 **금융 SI 프로젝트에서 재사용 가능한 표준 개발 프레임워크를 구축하는 것**을 목표로 한다.

또한 구현 결과만 남기는 것이 아니라 각 단계별로 **기술문서와 소스코드, Git 이력을 함께 관리**하여 프로젝트가 어떻게 만들어졌는지 전체 과정을 추적할 수 있도록 한다.

---

## 2. 핵심 구축 목표

Team-Microserver의 핵심 구축 목표는 다음과 같다.

### 2.1 금융 SI 프로젝트에 적용 가능한 표준 개발 프레임워크 구축

Spring Boot를 기반으로 금융 SI 프로젝트에서 반복적으로 필요한 구조와 기능을 표준화한다.

단순한 샘플 애플리케이션이 아니라 실제 프로젝트에서 기본 골격으로 활용할 수 있도록 다음 영역을 고려하여 구축한다.

- 애플리케이션 기본 구조
- 공통 모듈 및 업무 모듈 구조
- 공통 설정 관리
- 인증 및 인가
- 예외 처리
- 로깅
- 데이터베이스 연동
- 공통 유틸리티
- API 개발 표준
- 외부 시스템 연계
- 운영 및 관리 기능

프로젝트마다 반복적으로 새로 구현되는 영역을 공통화하여 **개발 생산성과 품질을 높이고 프로젝트별 편차를 줄이는 것**이 목표다.

---

### 2.2 프로젝트 생성부터 단계적으로 직접 구축

기존 MicroServer 기술문서는 중요한 참고 자료로 활용한다.

다만 기존 프로젝트의 소스코드를 그대로 가져와 구성하는 방식이 아니라, 새로운 Spring Boot 프로젝트를 생성하는 단계부터 필요한 기능을 하나씩 직접 구현한다.

구축 과정은 다음 원칙을 따른다.

1. 필요한 기능과 구조를 먼저 이해한다.
2. 기존 MicroServer의 구현 방식과 기술문서를 참고한다.
3. 현재 프로젝트에 적합한 구조를 다시 설계한다.
4. 기능을 직접 구현한다.
5. 실행 및 테스트를 통해 정상 동작을 확인한다.
6. 구현 내용을 Markdown 기술문서로 정리한다.
7. 소스코드를 Git commit 후 GitHub에 push한다.

이를 통해 최종 결과뿐만 아니라 **프레임워크가 만들어지는 전체 과정 자체를 기술자산으로 축적**한다.

---

## 3. 표준 프로젝트 구조 확립

Team-Microserver는 기능 구현과 함께 프로젝트 전체 구조에 대한 표준을 확립한다.

기존 MicroServer에서 사용한 Maven 멀티모듈 구조와 Common, Runtime, Admin 등의 역할을 참고하여 기능별 책임을 분리하고 향후 확장이 가능한 구조를 설계한다.

주요 목표는 다음과 같다.

- Maven 기반 멀티모듈 프로젝트 구성
- 공통 기능과 업무 기능의 명확한 분리
- 모듈 간 의존성 최소화
- 공통 기능의 재사용성 확보
- 애플리케이션별 확장 가능한 구조 제공
- 개발자별 구현 방식의 편차 최소화

프로젝트가 커지더라도 특정 모듈에 기능이 집중되지 않고, **각 영역의 역할과 책임이 명확하게 유지되는 구조**를 지향한다.

---

## 4. 공통 기능 표준화

금융 SI 프로젝트에서 반복적으로 사용되는 기능을 공통 기능으로 구현한다.

초기에는 기본적인 공통 기능부터 구축하고 이후 단계적으로 기능을 확장한다.

주요 대상은 다음과 같다.

### 4.1 애플리케이션 공통

- 환경 설정 관리
- 공통 상수 및 코드
- 공통 유틸리티
- 공통 응답 구조
- 공통 메시지 처리
- 공통 Validation

### 4.2 보안

- Spring Security 기반 인증/인가
- ID/PW 인증
- JWT 기반 인증
- OAuth2 확장 가능 구조
- URL 및 권한 기반 접근 제어
- 비밀번호 및 중요 정보 보호
- 보안 관련 공통 필터

### 4.3 데이터 처리

- DataSource 설정
- MyBatis 연동
- Transaction 처리
- 공통 데이터 접근 구조
- 다중 DataSource 확장 고려

### 4.4 예외 및 로그

- 공통 Exception 구조
- Global Exception Handler
- 오류 코드 및 메시지 관리
- Logback 기반 로깅
- 요청/응답 로그
- 추적 가능한 로그 식별자

### 4.5 API 개발

- REST API 개발 표준
- Controller / Service / Repository 역할 정의
- 요청 및 응답 객체 표준
- Swagger / OpenAPI 기반 API 문서화
- 공통 API 응답 및 오류 처리

이러한 기능을 표준화하여 업무 개발자는 공통 기능을 반복 구현하지 않고 **업무 로직 개발에 집중할 수 있도록 한다.**

---

## 5. 금융 시스템 연계 기반 구축

금융 SI 프로젝트에서는 내부 시스템 및 외부 시스템과의 연계가 매우 중요하다.

Team-Microserver는 일반적인 REST API뿐만 아니라 금융 시스템에서 자주 사용하는 전문 기반 연계까지 확장 가능한 구조를 목표로 한다.

주요 대상은 다음과 같다.

- REST API 연계
- MCA 연계
- EAI 연계
- FEP 연계
- 전문 Header / Body 구조
- 전문 생성 Builder
- 전문 Parsing
- 송수신 공통 처리
- 연계 오류 및 Timeout 처리
- 연계 로그 및 추적 정보 관리

초기 단계에서는 기본 구조와 인터페이스를 구축하고 이후 실제 연계 방식을 추가할 수 있도록 **확장 가능한 연계 아키텍처**를 구성한다.

---

## 6. 개발 표준과 개발자 경험 개선

프레임워크는 기능만 제공하는 것이 아니라 개발자가 일정한 방식으로 개발할 수 있도록 명확한 개발 기준을 제공해야 한다.

Team-Microserver는 다음 항목을 함께 표준화한다.

- 프로젝트 생성 및 실행 방법
- 패키지 및 모듈 구성 방법
- 클래스 Naming 규칙
- Controller 개발 방법
- Service 개발 방법
- 데이터베이스 연동 방법
- 예외 처리 방법
- 로그 작성 방법
- 공통 기능 사용 방법
- 테스트 및 확인 방법

표준 개발 절차를 문서화하여 새로운 개발자가 프로젝트에 참여하더라도 **프레임워크 구조와 개발 방법을 빠르게 이해할 수 있도록 한다.**

---

## 7. 개발 환경 표준화

Team-Microserver의 표준 개발 IDE는 **Visual Studio Code(VS Code)** 를 사용한다.

기존 Eclipse 또는 Spring Tool Suite(STS) 중심의 개발 가이드는 현재 프로젝트에 맞게 VS Code 기준으로 재정리한다.

개발 환경은 다음 항목을 표준화한다.

- Java 개발 환경
- Maven
- Visual Studio Code
- VS Code Java Extension
- Lombok
- Git / GitHub
- Spring Boot 실행 및 Debug
- Maven Build
- Markdown 문서 작성 및 Preview

운영체제에 따른 차이가 필요한 경우 Windows와 macOS 환경을 구분하여 가이드한다.

---

## 8. 문서와 소스코드의 동시 관리

Team-Microserver에서는 **구현과 문서화를 하나의 작업 단위로 관리**한다.

각 구축 단계는 다음과 같이 완료한다.

```text
기능 분석
   ↓
구조 설계
   ↓
소스코드 구현
   ↓
실행 및 테스트
   ↓
Markdown 기술문서 작성
   ↓
Git Commit
   ↓
GitHub Push
```

즉, 소스코드만 먼저 구현하고 문서는 나중에 작성하는 방식이 아니라 **각 단계가 완료될 때 문서와 소스코드가 함께 존재하도록 관리**한다.

이를 통해 다음과 같은 효과를 기대한다.

- 소스코드와 기술문서의 불일치 최소화
- 개발 과정 추적 가능
- 변경 이력 확인 가능
- 신규 개발자의 학습 자료 활용
- 향후 프로젝트 적용 시 참고 자료 확보

---

## 9. 단계적 구축과 검증

Team-Microserver는 처음부터 모든 기능을 한 번에 구현하지 않는다.

프로젝트의 기본 골격부터 시작하여 작은 단위로 기능을 추가하고 각 단계에서 정상 동작을 확인한다.

기본적인 구축 흐름은 다음과 같다.

```text
프로젝트 시작
    ↓
Spring Boot 프로젝트 생성
    ↓
프로젝트 기본 구조 구성
    ↓
멀티모듈 구조 구성
    ↓
공통 기능 구현
    ↓
보안 및 인증 구현
    ↓
데이터베이스 연동
    ↓
예외 및 로그 표준화
    ↓
API 개발 기반 구축
    ↓
금융 시스템 연계 기능 확장
    ↓
운영 및 관리 기능 확장
```

각 단계는 가능한 한 독립적으로 실행하고 검증할 수 있도록 구성한다.

문제가 발생했을 때 어느 단계에서 문제가 발생했는지 쉽게 확인할 수 있도록 **작고 명확한 단위로 구축하는 것**을 원칙으로 한다.

---

## 10. 재사용 가능한 기술자산 확보

Team-Microserver의 최종 목적은 한 번의 학습이나 테스트로 끝나는 프로젝트를 만드는 것이 아니다.

구축된 결과물을 이후 금융 SI 프로젝트에서 재사용할 수 있는 기술자산으로 축적한다.

최종적으로 다음 자산을 확보하는 것을 목표로 한다.

| 구분 | 구축 자산 |
| --- | --- |
| 소스코드 | 표준 Spring Boot 기반 프레임워크 |
| 프로젝트 구조 | Maven 멀티모듈 및 패키지 구조 |
| 공통 기능 | 인증, 보안, DB, 로그, 예외, API 등 |
| 연계 기능 | REST, MCA, EAI, FEP 확장 기반 |
| 개발 표준 | 개발 방법 및 구현 규칙 |
| 기술문서 | 단계별 Markdown 구축 가이드 |
| 형상관리 | 단계별 Git commit / GitHub 이력 |
| 운영 지식 | 구축 과정에서 발생한 이슈와 해결 방법 |

이러한 자산을 지속적으로 개선하여 새로운 프로젝트 시작 시 **기본 프레임워크와 가이드로 활용 가능한 수준**까지 발전시키는 것을 목표로 한다.

---

## 11. 최종 구축 방향

Team-Microserver가 지향하는 최종 모습은 다음과 같다.

> **금융 SI 프로젝트에서 반복적으로 필요한 기술 요소를 표준화하고,  
> 프로젝트 생성부터 공통 기능과 금융 연계 기능까지 직접 구축한  
> 재사용 가능한 Spring Boot 기반 표준 개발 프레임워크를 확보한다.**

그리고 그 구축 과정 전체를 Markdown 기술문서와 Git 이력으로 남겨 **소스코드, 개발 표준, 구축 경험을 하나의 기술자산으로 관리**한다.

---

## 12. 구축 원칙 요약

프로젝트 전체 과정에서는 다음 원칙을 유지한다.

1. **기존 MicroServer는 참고하되 소스코드는 직접 구축한다.**
2. **프로젝트 생성부터 단계적으로 기능을 추가한다.**
3. **각 단계는 실행과 테스트를 통해 검증한다.**
4. **공통 기능은 재사용 가능한 구조로 구현한다.**
5. **금융 SI 프로젝트 적용 가능성을 기준으로 설계한다.**
6. **VS Code를 표준 IDE로 사용한다.**
7. **구현 단계마다 Markdown 기술문서를 작성한다.**
8. **문서 작성과 함께 Git commit / GitHub push를 진행한다.**
9. **소스코드와 문서의 상태를 항상 일치시킨다.**
10. **최종 결과를 향후 프로젝트에 적용 가능한 기술자산으로 축적한다.**
